# Changelog

All notable changes to Nyachi. Versions follow [Semantic Versioning](https://semver.org/);
a `-beta.N` suffix marks a pre-release from the `develop` line.

## [2.1.0-beta.5] - 2026-11-06

### Codename

Sora

The Web build is usable for the first time: beta.4's Web release aborted on
startup, and pictures from instances that send no CORS headers never rendered
there. Alongside those fixes the settings page loses its form-looking search
field, and notifications gain type filters and per-class Android channels.

### Fixed

- **Nyachi's Web build no longer crashes on launch.** The residency bootstrap
  read `dart:io`'s `Platform` unconditionally, which the Web does not have, so
  `Unsupported operation: Platform._operatingSystem` aborted startup before the
  first screen. Residency now decides from `defaultTargetPlatform` and returns
  early on the Web, where there is no tray, window manager, or foreground
  service to manage.
- **Images that lack CORS headers render on the Web.** The canvas renderer
  fetches image bytes, and the browser refuses that cross-origin without
  `Access-Control-Allow-Origin`, so every such picture collapsed to the error
  placeholder. The Web error branch now re-renders through a DOM `<img>`,
  which the browser loads under image rules rather than fetch rules; other
  platforms keep the existing failure chrome.
- **Notification locale fallback no longer throws.** The announce resolution
  passed `basicLocaleListResolution` its arguments swapped, so an unsupported
  device language still failed; the preferred and supported orders are now
  correct and covered by a test.
- **Rapid notification filter switches cannot show the wrong rows.** Two
  in-flight refreshes could land out of order; responses whose filter changed
  mid-flight are now dropped.

### Changed

- **Settings search is a `SearchBar` on top of the page.** The field looked
  like a form input and scrolled away with the list. A flat Material
  `SearchBar` (elevation zero) now sits above the list and filters in place as
  you type, so no separate search page is involved.
- **Notifications filter by type.** A chip row (All / Mentions / Reactions /
  Boosts / Follows / System) reloads the list with the matching `includeTypes`,
  realtime arrivals of a filtered-out type are held back, and every row carries
  its event-class icon. Android groups system notifications into three
  channels.
- **The Web build shows a splash while it loads** instead of a blank page, on
  the app's own light and dark surfaces, removed once the first frame paints.
- Generated sources are no longer tracked: `build_runner` outputs and the
  gen-l10n directory are deterministic artifacts regenerated by every build.

## [2.1.0-beta.4] - 2026-11-04

### Codename

Kumo

A corrective release on top of beta.3: two review passes over the new code
found ten real defects, all fixed here. beta.3's Android background
notifications were effectively dead (the foreground service never started),
which is the main reason to prefer this build.

### Fixed

- **Android background notifications work.** The foreground service never
  actually started: the manifest lacked the plugin's `<service>` declaration.
  The realtime socket also stayed open in the background now (it used to be
  torn down on pause, leaving notifications without a source), and returning
  to the foreground no longer opens a second connection.
- **System notifications reach everyone and behave.** Devices set to a
  language the app does not ship no longer kill every notification with an
  error; notifications are skipped while the app is in the foreground instead
  of duplicating the in-app list; same-title events no longer overwrite each
  other in the system shade.
- **Drafts no longer fork.** A transient failure while saving to the server
  used to split one logical draft into permanently duplicated rows; the
  fallback copy now keeps the server identity, recovery updates in place, and
  the panel dedupes leftovers. An expired session on the autosave paths
  preserves typed content in the local table instead of losing it.
- **The chat transcript stays still.** A message arriving while you read
  history no longer slides the text under you, and sending from mid-history
  keeps the loaded pages instead of teleporting to the top.
- **The profile header keeps the divider between the first two notes.**

## [2.1.0-beta.3] - 2026-11-04

### Codename

Kumo

Fixes on top of beta.2, all from hands-on use of the previous build.

### Added

- **System notifications from the realtime stream.** A notification that
  arrives while the app is in the background now raises a Windows, Linux or
  Android system notification, worded in the app's language. Tapping it brings
  the window forward. Android's foreground service, which keeps the connection
  alive, is now actually started instead of being left unstarted.
- **Settings search and grouping.** The settings list is grouped by owner
  (this server, this app, advanced) and the search field jumps straight to any
  page.

### Changed

- **Settings now open from the account.** The top of settings is your account:
  it leads to the account hub, which now also holds the profile, privacy, email
  and security pages — everything that changes you on the server. They are no
  longer separate top-level entries.
- **Completions accept with Tab only.** Enter now always inserts a newline, so
  typing a colon can never silently replace text with an emoji.

### Fixed

- **Profile banners and avatars fill their containers.** The banner spans the
  full window instead of shrinking to the content column, keeps a readable
  height on narrow windows, and the avatar image fills its circle. Applies to
  both your own profile and other users'.
- **The reaction button shows the reaction you followed.** Reacting to a note —
  including by following someone else's reaction — no longer replaces the
  emoji with a generic heart icon.
- **Settings sub-pages open again.** Every settings destination is registered
  with the router, so no entry lands on a not-found page.
- **The emoji catalogue reports failures** instead of collapsing to the
  built-in set, with a retry action.
- **Remote custom emoji resolve in the reaction picker** through the note's
  emoji map.
- **Tab switching animates** on both narrow and wide layouts.

## [2.1.0-beta.2] - 2026-11-03

### Codename

Kumo

Seven planned domains shipped at once: the composer, the reading surfaces,
account settings, and notification delivery. Minor rather than patch, because
the surface area grew — new settings pages, new composer tooling, and a
realtime connection the app did not have before.

### Highlights

- **The composer works like a real editor.** Drafts persist per context, both
  server-side where the instance supports it and locally as a fallback; the
  header avatar opens drafts, scheduled posts and same-instance account
  switching. Typing `@`, `#` or `:name` opens a completion list anchored in the
  text. One paperclip attaches either a local file or an existing drive file.
  Polls and attachments can coexist, and the preview is a toolbar mode.
- **Reading got faster and steadier.** The chat transcript opens at the newest
  message and loading older history no longer moves what you are reading; every
  feed loads at the scroll edge instead of a button. The note card has four
  actions plus a real menu (favorite, delete, report, copy link, memo, thread
  mute), a reacted note's button cancels the reaction, and a reply's detail page
  now shows the chain of ancestors above it.
- **Account settings are editable in the app.** Profile, privacy, per-event
  notification delivery, email, password and two-factor, and drive quota —
  each control mapped to a real API field, read fresh from the server on open.
- **Notifications arrive without a refresh.** One websocket carries both
  notifications and chat, web push works through the service worker, desktop
  keeps running in the tray, and Android runs a foreground service.
- **Caches are manageable.** Instance info, the emoji catalogue, notifications
  and the following list each report their size and can be cleared separately.

### Composer

- Drafts are stored per context (text, CW, visibility, poll, scheduled time).
  Where the instance supports `notes/drafts` they live on the server, otherwise
  in a local table capped at 50 per account. A draft with no substantive content
  is deleted rather than saved, so blank drafts no longer accumulate.
- A reply's draft is stored separately from the timeline draft, so composing a
  reply never overwrites what you were writing.
- The header avatar opens a panel listing drafts, scheduled posts and other
  accounts on the same instance. Switching accounts from there stays in the
  composer instead of jumping to the timeline.
- Visibility, local-only and post are grouped flush to the trailing edge.
- Reaction acceptance moved into a submenu and now offers all five values the
  API accepts, including remote-only variants.
- Live preview is a toolbar toggle that replaces the editor, with a footnote
  naming what it does not render.
- `@` completes from your following list plus a remote user search after two
  characters; `#` from instance trends; `:` from the emoji catalogue. Arrow
  keys, Enter and Escape work, and completing mid-sentence does not leave a
  double space.
- Completions are accepted only with Tab or a click; Enter always inserts a
  newline, so a typed `:` can never silently replace text with an emoji.
- One paperclip button offers a local file or a drive file. The drive picker
  browses folders, can create one inline, and attaches by file id without
  re-uploading.
- Polls and attachments no longer exclude each other, and attachments survive
  the autosave now that a poll can sit beside them.
- Fixed: text typed while a draft was still loading could be overwritten by the
  restored draft, and because local drafts drop attachments, files vanished
  while the text survived. A restore now only fills an untouched composer.

### Reading

- The chat transcript is a reversed list: it opens at the newest message, and
  loading older pages appends below the viewport instead of shifting what is on
  screen.
- Note actions are four buttons — reply, renote, react, detail — with the rest
  behind an overflow menu: favorite, delete (own notes, with confirmation),
  report (requires a comment; the endpoint reports the author), copy link, user
  memo, and thread mute.
- A note you already reacted to shows a cancel button; the picker still adds or
  changes reactions.
- The detail page renders the ancestor chain from `notes/conversation` above the
  focused note, joined by reference lines, with replies below. Tapping an
  ancestor opens its own page.
- Custom emoji are grouped under sticky category headers in both the reaction
  picker and the insert sheet, with uncategorized emoji last.
- Home timeline, notifications, explore search, detail replies and chat all load
  at the scroll edge; the load-more buttons are gone.

### Settings

- New pages: profile (name, bio, fields, birthday, location, bot/cat, avatar and
  banner), privacy (mute and block lists, default visibility and local-only for
  new notes), notifications (per-event delivery), email, security (password,
  two-factor with secret entry, sign-in history) and drive (quota).
- Default visibility and local-only are stored locally and read by the composer,
  so a new note starts from your preference rather than a hardcoded public.
- Cache management lists entry count and byte size per kind and clears one kind
  or everything.

### Interface

- Tab switching animates with a directional slide: horizontally on narrow
  windows where the tabs sit in the bottom bar, vertically on wide screens
  where they sit in the sidebar. Branch state is preserved during the
  animation.

### Delivery

- One websocket carries the main channel for notifications and a chat channel
  per open thread. Joining and leaving a thread happens on the live connection,
  and both consumers deduplicate by id because a reconnect replays.
- Web push: the service worker shows a system notification and focuses an
  existing tab (or opens the route) on click. Setup registers the browser
  subscription with the instance; disabling unsubscribes the browser first.
- Desktop keeps a tray icon and hides to it on close instead of quitting. On
  Linux the tray uses the StatusNotifierItem D-Bus standard via nativeapi,
  replacing the libappindicator C library that current distributions no longer
  ship, and the tray icon loads from the bundled assets rather than a file
  path that was never packaged.
- Android declares notification and foreground-service permissions and runs a
  foreground service so the connection survives backgrounding.

### Fixed

- Web requests no longer try to set `User-Agent`, a header browsers refuse; the
  SDK set it unconditionally and every request logged a console warning.
- The appearance picker no longer offers "System color" on the web, where no
  system palette exists and the choice silently did nothing.
- Opening a note from a list never loaded its replies, because the controller
  returned early whenever a cached override existed — which is exactly what a
  pushed note has.
- Reacting via the picker's existing-reaction chips did not render remote
  emoji (`:name@host:`); they now resolve through the note's own emoji map.
- A failed emoji-catalogue load silently shrank the picker to the built-in
  set; it now shows an explicit error with a retry.

## [2.0.0-beta.9] - 2026-11-01

### Codename

Baka

### Back navigation

- Back now undoes one layer of whatever is actually open, and means the same
  thing for the platform back button, the browser's back button and the
  on-screen arrows: full-screen views close first, then one detail-panel entry
  at a time, then pushed pages, then a non-timeline tab returns to the timeline.
- At the timeline with nothing open, back keeps the platform's own behaviour:
  Android and desktop close the app, and the browser leaves the page rather than
  navigating away mid-session.
- The wide-screen detail panel could not be closed with back at all before; it
  is state rather than a route, so it is now unwound explicitly.

### Custom emoji reactions

- A reaction using one of the instance's own custom emoji did not render.
  Misskey writes those as `:name@.:` and omits them from the note's
  `reactionEmojis`, and all three render paths read any `@host` as remote. `@.`
  now resolves against the local catalogue, while a genuinely remote host still
  resolves against the note's own emoji list.

### Appearance

- New "System color" accent that follows the platform's Material You palette,
  alongside instance color and the fixed swatches.
- Accent swatches show their labels and no longer rely on tooltips, so the
  choice is readable at every width, including in the first-run wizard.

### Fixed

- The lock file resolved against a local mirror, which made CI's
  `git diff --exit-code` guard fail on every run and blocked releases.
- `dynamic_color` was registered for Windows but not for Linux or macOS, so
  following the system palette did nothing on those platforms.
- The app reported a hard-coded "Version 0.1.0+1", which had drifted from the
  real build version. It now reads the version the build actually carries, and
  the About page offers the newest published release when one is newer.
- The app icon baked a hard square background; it now has rounded corners. The
  web icon used a different artwork from the desktop and mobile builds and now
  matches them.
- Instance announcements sat on the About page beside the app's own version and
  licences, though they come from the account's server; the entry moved to the
  accounts page.

  `android/gradle.properties` and is dropped at AGP 10.
